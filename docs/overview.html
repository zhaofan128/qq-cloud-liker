Deploy

四步，五分钟

  1. 推到 GitHub

    建议 public 仓库 —— Actions 完全免费；私有仓库每月只有 2000 分钟，跑 5 分钟粒度会超额。

  2. 抓 Cookie

    浏览器登录 user.qzone.qq.com，F12 → Network → 复制请求头里的整段 Cookie，必须含 p_skey。

  3. 配 Secrets

    QQ_UIN、QQ_COOKIE 存 Secret；QQ_FRIENDS 存 Variable，逗号分隔。

  4. 先演练再真跑

    Actions 里手动触发，dry_run=1 看日志无误，再改 0 正式执行。

Offline

为什么任务跑起来你还是「离线」

做法好友看到的状态是否挤掉手机
本项目：复用网页 Cookie 发请求完全不变不会
NapCat / Lagrange 协议端登录显示「电脑在线」可能会
手机 QQ 手动切「隐身」+ 本项目离线不会
结论：脚本从不调用登录接口，只是带 Cookie 发普通 HTTPS 请求，服务端不会新建会话。想让列表里显示离线，在手机 QQ 里切成隐身即可 —— 隐身不影响点赞，两者互不干扰。

Risk

必须知道的四件事

非官方接口。名片赞与空间点赞均无公开 API，本项目使用网页端私有接口，属于自动化操作，违反 QQ 用户协议，存在限制点赞或封号的概率。建议先用小号跑一周。

Cookie 会过期。通常几天到几周，失败时 Actions 变红并邮件提醒，重抓一次更新 Secret 即可。

异地 IP 是最大变量。Actions 每次从不同机房 IP 出口，同一 Cookie 频繁跨地访问易触发安全验证。脚本已做串行请求 + 1.5 秒随机间隔 + 出错即跳过，但无法完全消除，追求稳定请放固定 IP 的 VPS。

不要提频。把间隔压到 1 秒以下只会加速触发风控，收益为零。
